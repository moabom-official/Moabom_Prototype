## 1. 제안 1 — 서비스화 준비 먼저, 영업은 그 다음

### 왜 준비가 먼저인가
- 기업에 컨택하는 순간 상대가 보는 것 = **회사 도메인 메일, 웹사이트**. `@gmail.com`으로 콜드메일을 보내면 신뢰도에서 시작부터 손해.
- 그런데 AWS Activate(스타트업 $1,000 크레딧)가 요구하는 것이 정확히 이 두 가지(웹사이트 + 도메인 메일). **어차피 영업에 필요한 준비를 하면 크레딧까지 따라오는 구조** — 겹치는 투자라 ROI가 높음.

### AWS Activate Founders 요건 (2026-07 공식 페이지·가이드 확인)

| 항목 | 내용 | 우리 상태 |
|---|---|---|
| 혜택 | **$1,000 AWS 크레딧** (+개발자 지원 크레딧 $350, 서드파티 가이드 기준) | — |
| 크레딧 유효기간 | 발급 후 **1~2년 내 만료** (승인 메일에서 확인) | — |
| 자금 요건 | 자기자금/부트스트랩 (기관투자·액셀러레이터 이력 없음), pre-Series B | ✅ 해당 |
| 회사 요건 | 설립 10년 이내, 직원 10명 미만, 매출/펀딩 $1M 미만 | ✅ 해당 |
| **회사 웹사이트** | "완전히 작동하는 회사 웹사이트" **필수** | ✅ 랜딩 라이브 (moabom-landing.vercel.app) — 단, 커스텀 도메인 연결 권장 |
| **비즈니스 이메일** | 회사 도메인과 일치하는 메일로 프로필·신청 작성 — 공식 가이드가 명시적으로 권장(사실상 필수) | ❌ **도메인 + 메일 개설 필요** |
| AWS 계정 | **유료 티어(Paid plan) 계정** 필요 (신규 생성 시 Free plan 말고 Paid 선택, 결제카드 등록) | ❌ 생성 필요 |

- **신청 링크(공식)**: https://aws.amazon.com/startups/credits/ → "Apply Now"
- 절차: AWS Builder ID 생성(개인 메일) → Activate 프로필 작성(**비즈니스 메일**) → 회사 정보 입력 → AWS 계정 연결 → 제출. **승인까지 5~10 영업일**.
- 신청 상태는 Credit Application Status 페이지에서 추적 가능.

### 준비 체크리스트 (순서대로)

1. **도메인 구매** — `moabom.com`(약 ₩2만/년) 또는 `.ai`(비쌈, 연 10만+) / `.io`(연 5만±). 가용성 확인 후 회의에서 결정. 구매처는 Cloudflare Registrar(원가 판매) 추천.
2. **랜딩페이지에 커스텀 도메인 연결** — Vercel 설정에서 5분 작업. 웹사이트 도메인 = 메일 도메인 일치가 심사에 유리.
3. **도메인 메일 개설** — 3가지 옵션:
   - **A. Google Workspace** (~₩8,000~9,000/인/월): 정석. `contact@` 1계정만으로 시작 가능.
   - **B. Zoho Mail 무료 티어**: 커스텀 도메인 5계정 무료, 웹메일 위주.
   - **C. Cloudflare Email Routing(수신, 무료) + Gmail 별칭 발신(무료)**: ₩0. SPF/DKIM 설정하면 발신 신뢰성도 확보.
   - 내 기울기: **시작은 C(0원)로 Activate 신청까지 통과 → 영업이 본격화되면 A로 업그레이드**.
4. **AWS 계정 생성** (Paid plan + 결제카드) → **Activate 신청 제출**.

### 회의에서 논의할 포인트

- **도메인 이름**: moabom.com이 살아있는지 확인하고 확정.
- **⚠️ 사업자등록**: 신청서에 회사 정보를 기재함. 법인 필수는 아니라는 후기가 많지만, 어차피 B2B 계약·세금계산서 단계에선 필요 → **"언제 할지"** 를 논의 (지금 당장은 아닐 수 있음).
- **⚠️ 크레딧은 AWS에서만 사용 가능**: 현재 운영은 Azure(학생 크레딧으로 커버 중). 받은 크레딧으로 뭘 돌릴지 정해야 의미가 있음. 후보: ① B2B 데모/신규 워크로드를 AWS에 구축 ② Azure 학생 크레딧 소진 대비 이전 준비 ③ GPU·Bedrock 실험.
- **예상 총비용**: 도메인 ~₩2만/년 + 메일 ₩0(옵션 C 기준). 사실상 도메인 값만 내면 됨.

## 2. 제안 2 — 방향성: 멘토님 질문으로 정리하고, 답변 기반으로 설계

솔직히 방향성은 나도 아직 모르겠음. 랜딩페이지 만들 때 임시 가정을 깔긴 했지만(아래 각 질문에 표기) 확신이 없으니, **우리끼리 추측으로 확정하지 말고 멘토님(B2B 세일즈 경험자) 답변을 받아서 설계**하는 게 맞다고 생각함. 회의에서 질문 문안을 확정해서 회신드리자.

### Q1. 소비재 기업 안에서 타겟 팀을 하나로 정해야 하는가? 정한다면 어디?

- 기업엔 마케팅팀·CS팀·상품기획팀 등이 있는데, 초기 영업에서 **딱 하나의 타겟을 정해야 하는지**, 정한다면 **어느 팀의 페인이 가장 지불의사로 이어지는지**.
- 현 상태: 랜딩페이지는 타겟 미확정이라 유즈케이스 3카드(마케팅·상품기획·VOC)로 다 열어둔 상태 — 임시 가정이었음.
- 참고: Syncly의 타겟도 마케팅·상품기획·CX로 우리 3카드와 거의 동일. 그들은 CX(VoC 분석)로 시작해서 소셜(마케팅)로 확장했음.
- 참고 2: 우리가 들은 유일한 실제 페인 = 아모레 지인의 "제품 리뷰 수작업 수집"(마케팅/상품기획 쪽 업무).

### Q2. 기업 컨택 전에 테크 → 다른 도메인(뷰티·식품 등)으로 미리 피벗 개발해야 하는가?

- 현 상태: 수집·분석·프롬프트·데이터 전부 테크 리뷰 기준으로 개발돼 있음. 랜딩은 "도메인 무관, 확장 가능"으로 프레이밍(이것도 임시 가정).
- 트레이드오프:
  - **미리 개발**: 컨택 시 해당 도메인 데모를 바로 보여줄 수 있음 ↔ 어느 도메인일지 모른 채 개발하는 리스크, 시간 소모.
  - **컨택 후 대응**: 낭비 없음 ↔ "테크만 되네요"로 첫인상에서 밀릴 수 있음.
- 내 기울기(가설): 풀 피벗은 아니고, **비테크 카테고리 1개(예: 뷰티)로 샘플 보고서 1~2건만 만들어 "확장 증명"** 해두는 절충안. 멘토님 답변으로 검증하고 싶음.

### Q3. 유튜브 단일 채널 → 멀티채널 전환이 필요한가? 미리 개발해놔야 하는가?

- 현 상태: 유튜브(자막+댓글)만 분석. Syncly는 틱톡·릴스·이커머스 리뷰까지 멀티채널.
- 트레이드오프: 멀티채널은 커버리지가 세일즈 포인트 ↔ 채널별 수집 인프라 비용 큼 + 우리 차별점(영상 리뷰 심층 분석: 리뷰어 의견 + 시청자 댓글 + 합의도 정량화)이 희석될 수 있음.
- 질문 포인트: **기업 고객이 "채널 커버리지"와 "채널당 분석 깊이" 중 뭘 사는지** — 이건 영업 경험자만 아는 영역.

### (추가 질문 후보) Q4. Syncly와 어느 지점에서 달라야 산다고 보시는지

- 멘토님이 Syncly를 지목하셨으니, 역으로 "저 팀과 정면승부는 아닐 텐데, 어떤 쐐기(wedge)가 유효해 보이는지" 물어보면 답변이 구체적으로 나올 것 같음.

## 3. Syncly 벤치마크 (멘토님이 지목한 경쟁 제품)

### 회사 개요
- 운영사 **딥블루닷(Deep BlueDot)** — **Y Combinator W23** 출신, 2023년 시드 35억 원(SBVA=소프트뱅크벤처스, Fast Ventures, 샌드버드 김동신 대표 등).
- 공개 지표: **ARR $2M**, NDR 120%. 고객: LG생활건강, 교보생명(Kyobo Life), 마이리얼트립, 팔도 등.

### 제품
- 시작은 **VoC 분석**(CS 티켓·리뷰·설문 통합 → AI 토픽 분류 → 대시보드).
- 최근 **Syncly Social** 출시 — 틱톡·릴스·이커머스 리뷰까지 소셜 리스닝 확장, AI 노이즈 필터링, "Hey Syncly"로 질문하면 자동 리포트.
- 포지셔닝: "소비자 반응을 상품 기획과 마케팅 전략으로 연결" — 요약이 아니라 실행 가능한 결론.

### 시사점 (내 해석)
1. **시장 검증**: "흩어진 고객 목소리 → AI 분석 → 기획/마케팅 인풋" 시장에 YC·소프트뱅크가 돈을 넣었고 ARR $2M이 나옴. 우리가 이상한 걸 만들고 있는 게 아님.
2. **멘토님의 프레임**: 멘토님은 우리를 이 카테고리(VoC/소셜 리스닝)로 보고 있음. 회신할 때 이 카테고리 언어로 답하면 대화가 빨라짐.
3. **차별점 후보**: Syncly는 넓게(멀티채널 토픽 분류), 우리는 깊게 — **영상 리뷰 1건을 자막(전문 리뷰어 의견)+댓글(소비자 반응)로 파고 리뷰어 간 합의도까지 정량화(N/N)**. "영상 리뷰 심층 분석"은 그들 커버리지의 빈 곳일 수 있음.
4. **경계**: 자금·인력 격차가 크므로 기능 넓히기 경쟁은 필패. 좁은 쐐기를 정하는 게 오히려 생존 전략 → Q1~Q4가 그 쐐기를 정하기 위한 질문들.
5. (선택) 무료 데모/체험 신청해서 직접 써보고 회의 때 같이 보는 것도 방법.

## 4. 회의에서 정할 것

1. **제안 1 실행 여부 + 역할 분담** — 도메인 구매 / 메일 세팅 / AWS 계정·Activate 신청 각각 누가, 언제까지.
2. **도메인 이름 확정** (moabom.com 가용성 확인).
3. **멘토님 회신 문안 확정** — Q1~Q3(+Q4) 질문 + "우리 목표" 한 단락. ※ 목표 문장도 회의에서 한 줄로 합의 필요 (예: "리뷰 분석을 수작업으로 하는 소비재 기업 실무자의 시간을 줄이는 B2B 도구" — 초안, 수정 환영).
4. **사업자등록 논의 시점** 결정.
5. (선택) Syncly 체험 신청 여부.
